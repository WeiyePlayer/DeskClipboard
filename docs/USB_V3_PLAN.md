# 桌面剪切板项目计划

调研日期：2026-10-17。对象是当前这块已连通的 LCDWIKI ES3C28P（ESP32-S3 N16R8，2.8 寸电容屏），使用电脑是这台 Mac。

## 进度

2026-10-17 卡片外观补齐：文字和图片卡片的位图先铺与屏幕一致的灰色，再绘制白色圆角卡片，避免原先白色底图把圆角填平。图片尺寸移到缩略图下方独立一行，使用卡片内容区宽度显示。此次仅更新 Mac 端渲染，无需再次烧录。5 项渲染测试及 LVGL 点击模拟通过，预览为 `firmware/sim/build/cards-rounded.png`。

2026-10-17 顶栏按参考图调整：去掉左上角回到顶部按钮（实体 BOOT 的回顶功能保留）；「剪贴板 / 常用语」在屏幕中央使用灰色圆角槽和白色内嵌选中块，两侧整块区域都能点击。右上角白色圆形「⋯」统一承载页面操作和后续设置，目前为清空历史、暂停 / 继续记录。Mac 端标签改为适配选中块的 48×24 RGB565 图片，固件与 Mac 端需一起更新。

本次 ESP-IDF 编译、LVGL 页面切换及菜单点击模拟、8 项相关主机测试通过。用户按住 BOOT 重新插上 USB 后，已备份旧应用分区到 `backups/pre-header-20261017-app.bin`，在 `0x10000` 写入新固件并通过 Flash 哈希校验。看门狗复位后，Mac 端确认协议 3 重连、2 条历史及界面资源同步成功；实板外观和物理触摸手感尚待用户确认。模拟器实渲染预览位于 `firmware/sim/build/header-clipboard.png`。

阶段 1 已在这块板上跑通：示例中文和 PNG/TIFF 能贴进 TextEdit。

面板固件和 Mac 端已经按照片的「剪贴板 / 常用语」写好。Mac 端用 SQLite 存历史和原图，拆出手机号、链接、邮箱和验证码，并把卡片画成 RGB565。开发板用 LVGL 显示列表，点正文、胶囊和「⋮」通过 USB 帧回传。按住 BOOT 再插上才能烧录；普通重启进不了下载模式。

2026-10-17 修了「顶栏加载到一半就停」：固件收数据时，环形缓冲区一读空就把整帧丢掉，超过一个 USB 包、分几批到达的帧（卡片、较长的标签）永远收不到确认。`link.c` 改为读空时继续等待，帧内停顿超过 500 ms 才放弃。Mac 端读串口不再白等 200 ms，确认快了约 10 倍；卡片上的文字和缩略图原先上下颠倒，`render.py` 已改正。固件修复需要重新烧录。

同日第二个问题：同步后再复制一条，开发板会重启（USB 掉线），Mac 端随即崩溃退出。原因是板上每画一次卡片就从 LVGL 自带的 64 KB 内存池里复制一份像素且从不释放，几张卡片就把池子用光，LVGL 下一次分配拿到空指针而崩溃。`ui.c` 改为直接显示 PSRAM 里的原图，LVGL 改用系统堆（`sdkconfig.defaults`）；HELLO 附带上次重启原因。Mac 端漏收确认或串口断开时不再退出，而是记日志、等板子回来后重新全量同步。

## 结论

这件事做得成。复制过的文字、图片，以及用户收藏的条目，都可以在屏幕上点一下，贴进 Mac 上当前聚焦的输入框。

没有找到可以直接烧录、并覆盖「历史 + 收藏 + 图片 + 中文一键粘贴」的开源整机项目。接近的仓库分成两类：Mac 上的剪切板软件，以及 ESP32 宏键盘 / Stream Deck。两类都要自己接起来。

推荐架构是：开发板只做插在电脑上的触摸遥控器，历史和原图放在 Mac 常驻程序里。点选后，Mac 程序把对应内容写入系统剪切板，再向当前应用发送 Command-V。

USB 键盘模拟只适合短 ASCII。它写不进系统剪切板，也贴不出图片；中文会按键盘布局变成乱键。本计划不走这条路。

## 这块板的约束

厂家页面与本仓库实测一致：

- ESP32-S3，240 MHz 双核，16 MB Flash，8 MB PSRAM。当前 USB 为乐鑫原生 USB Serial/JTAG，VID:PID `303A:1001`，串口曾为 `/dev/cu.usbmodem1101`。
- 屏：ILI9341V，SPI，240×320。片选 IO10，DC IO46，时钟 IO12，MOSI IO11，MISO IO13，背光 IO45。
- 触摸：FT6336G，I2C。SDA IO16，SCL IO15，复位 IO18，中断 IO17。实物是带触摸的 ES3C28P。
- Type-C 接在 ESP32-S3 的 USB 引脚 GPIO19/20 上。同一组引脚可以改成 TinyUSB 设备；改完后，平时的 USB Serial/JTAG 日志会让出来。烧录仍用 BOOT 进下载模式，出厂备份已在 `backups/`。
- 另有 MicroSD、ES8311 音频、麦克风和电池座。剪切板第一版用不到。

屏只有 240×320，完整中文字库有数 MB，原图也放不进日常列表。列表上的每一行由 Mac 渲染成小图再发给板子，板上只负责显示和回传点击。这样中文、表情和图片缩略图都不用在板上做字体和图像解码。

## 产品行为

插上 Type-C 后，竖屏列出最近复制的内容。点一行，该内容出现在 Mac 当前的输入框里。长按把该条放进收藏，收藏页同样点按粘贴。

第一版支持：

- 纯文本，包含中文、换行和表情。
- 图片：以 PNG 写入剪切板；同时写入 TIFF，兼容只认 TIFF 的应用。
- 最近列表与收藏列表。
- 跳过密码管理器标记为隐蔽的剪切板项，不显示、不保存。
- 电脑端菜单栏显示已连接或未连接。

第一版不做：

- 富文本、HTML、文件列表粘贴。
- 多台电脑同步、云端、手机。
- 电池离座使用、Wi-Fi 传输。板子支持电池和 Wi-Fi，桌面场景用同一根 USB 供电和通信。
- 保留小智语音。新固件会换掉当前小智 2.0.2。回退命令已写在 [XIAOZHI.md](XIAOZHI.md)。
- Windows。Mac 跑通后，电脑端可以另写 Win32 剪切板和 Ctrl-V，协议不动。

粘贴时 Mac 程序先记住原来的剪切板，贴完再写回去，避免一次点选把用户刚复制的内容冲掉。若目标窗口处于安全输入（密码框一类），系统会拦住模拟按键；此时内容仍留在系统剪切板上，屏幕提示需要手动按 Command-V。

## 架构

```
Mac 应用复制文字或图片
        │
        ▼
常驻程序监听 NSPasteboard
  保存原文到本机数据库
  把每行渲染成小图
        │  USB 虚拟串口（TinyUSB CDC）
        ▼
ES3C28P 竖屏列表（最近 / 收藏）
        │  点按一条
        ▼
常驻程序写回 NSPasteboard，再发送 Command-V
```

数据以 Mac 为准。板上只缓存当前页的小图和条目编号，断线后向 Mac 要一页。20 条大约几百 KB 的小图，放 PSRAM 即可，不必上 SD 卡。

板上固件：ESP-IDF 5.4 或更新版本，LVGL，厂家引脚上的 ILI9341 与 FT6336。USB 使用 TinyUSB 设备模式的虚拟串口。日志走这条串口。Wi-Fi 和蓝牙在第一版关闭，避免和 USB、SPI 抢中断。

Mac 程序分两步写。先用 Python 加 PyObjC 做无界面验证，确认中文和图片能贴进真实输入框。通过后改成 Swift 菜单栏程序，便于申请辅助功能权限并常驻。

串口帧用长度前缀的二进制消息，内容是条目编号、种类、是否收藏，以及一行 JPEG 小图。板子只上行「粘贴这个编号」「切换收藏」。不把剪切板原文打进固件日志。

## 阶段

每个阶段都在实板上验收，再进入下一阶段。当前仓库只有 esptool，第一阶段要先装 ESP-IDF。

1. **粘贴通路**  
   固件枚举成 USB 虚拟串口。Mac 脚本收到一条命令后，把一句中文和一张 PNG 写入剪切板并发送 Command-V。  
   验收：备忘录和浏览器输入框出现这句中文；预览或支持贴图的输入框出现这张图。辅助功能未授权时，脚本给出明确提示。烧录仍可用 BOOT 加现有 esptool 流程，烧完能从 `backups/` 恢复小智。

2. **屏幕点选**  
   竖屏列出若干条由 Mac 发来的小图。点按把对应编号发回，Mac 贴出该条原文。  
   验收：五条里点任意一条，贴出的是该条，而不是最后一次系统复制。触摸坐标与竖屏一致。

3. **真实历史**  
   常驻程序监听系统剪切板变化，新复制的文字和图片进入「最近」，屏幕跟着更新。  
   验收：在 Mac 上复制三次文字和一次截图，屏幕顺序与复制顺序一致；点截图能贴图。隐蔽项不出现。

4. **收藏**  
   长按加入或移出收藏，收藏单独一页，重启 Mac 程序后还在。粘贴后恢复点选前的系统剪切板。  
   验收：收藏一条图片，再复制别的内容，从收藏页点回去仍能贴出原来的图。

5. **日常使用**  
   菜单栏状态、拔插重连、背光超时、列表滚动。空列表有一句话说明。  
   验收：拔掉再插上后无需重开程序；电脑睡眠唤醒后列表恢复。

## 风险与对应做法

- **模拟按键被系统拒绝。** 第一阶段就用真实输入框验证。安全输入场景改为屏幕提示，并保留系统剪切板内容。
- **不同应用要的图片类型不一样。** 同时写入 PNG 和 TIFF。第一阶段用预览和浏览器确认；聊天软件在第 3 阶段用用户实际在用的应用再试一次。
- **启用 TinyUSB 后，现在的 `303A:1001` 串口日志消失。** 开发日志改走虚拟串口。烧录失败时按住 BOOT 上电，仍走下载模式。
- **剪切板里有密码和隐私。** 只存在 Mac 用户目录；忽略隐蔽项；固件和串口日志不记录正文。程序不做网络上传。
- **换固件会暂时失去小智。** 出厂全片备份和竖屏 2.0.2 固件都在仓库里，恢复命令已有。新固件分区不要覆盖用户尚未另存的其他数据；当前 16 MB 备份已经包含烧录前的整片内容。
- **板级支持包的音频引脚与厂家 wiki 不完全一致。** 本项目不初始化音频，屏和触摸以厂家 wiki 及已跑通的小智显示为准。

## 验收口径

在这台 Mac 上，开发板插着 Type-C：

- 复制一段中文后，点屏幕上的对应行，文字进入当前输入框。
- 复制一张图片后，点对应行，图片进入能接受贴图的输入框。
- 收藏的条目在新的复制之后仍能一键贴回。
- 密码管理器复制的隐蔽内容不出现在屏幕上。
- 任一阶段失败时，可以用现有备份恢复小智 2.0.2。
